# MeowFish Cloud ☁️ ฅ(^•ω•^)ฅ

> The Cloudflare deployment project for **MeowFish** (local edition repository: pi-meowfish-agent, URL to be added once created), released and deployed independently.
> 🌐 中文: [README.md](README.md)

> 🌐 Live demo: [https://meowfish-agent.kdns.fr/](https://meowfish-agent.kdns.fr/) (what you deploy is what you get; sessions / character cards / configuration and credentials stay in your own browser only)

![version](https://img.shields.io/badge/version-1.0.0-7dd3fc) ![license](https://img.shields.io/badge/license-AGPL--3.0-orange) ![runtime](https://img.shields.io/badge/runtime-Cloudflare%20Workers-f6821f)

The UI / chat / role-play / model proxy run on a Cloudflare Worker — **zero persistence in the cloud**: sessions / character cards / configuration live only in each browser's localStorage, isolated by deviceId, so multiple people can share one deployment without seeing each other's data. Computer-access tools run through the **built-in SSH client in the Worker connecting directly to your server** (or an HTTPS + token fallback to a remote tool server).

## ✨ Features

- 🎭 Role-play (character card V2) + chat + session management — same feature set as the local edition
- 🛠️ **Built-in SSH client in the Worker**: zero-dependency X25519 / Ed25519 / AES-256-GCM; configure with `/ssh` and control remote servers directly
- 💻 **Web SSH terminal**: interactive browser terminal (WebSocket ↔ SSH shell/PTY), shared by the local and cloud editions
- 🌐 Web search (Bing / Baidu / Sogou first, Google / Brave as supplements; multi-engine aggregation and de-duplication; no approval needed)
- 🔒 **Zero persistence**: no database bindings — your data stays in your own browser
- 👥 Multi-user: isolated by deviceId
- 💬 Bilingual UI (中文 / English) · 🌗 Light/Dark themes · 📱 Mobile friendly

## 🚀 Deploy

**Requirements**: Node.js ≥ 18 + a Cloudflare account (the free plan is enough, no database required)

```bash
# 1. Install dependencies
npm install

# 2. Log in to Cloudflare (browser authorization)
npx wrangler login

# 3. Deploy (outputs https://your-subdomain.workers.dev)
npx wrangler deploy
```

**After deploying (3 steps)**:

1. Open your Worker URL in a browser → **Menu → Model Manager** → add a model (choose the "DeepSeek" or "OpenCode Zen" preset and enter your API key — it stays in this browser only)
2. Start chatting; to control a remote computer run `/ssh` and enter the server details (password or ed25519 private key — credentials stay in this browser only)
3. (Optional) Bind a custom domain: Cloudflare dashboard → Workers → your Worker → Settings → Domains & Routes → Add custom domain

**Local development**:

```bash
npx wrangler dev --port 8787   # open http://127.0.0.1:8787
```

## 🔧 Syncing with the main project

This directory is generated by the local edition repository's `node scripts/split-cf.mjs` (copies pure modules and rewrites imports, preserving the configured `wrangler.toml`, node_modules and git history). After updating the main project, re-run the script and commit the changes to this repository.

## 📁 Directory structure

```
src/
├── index.ts          Worker entry (SSE / /ui/* / static assets, memory state isolated by deviceId; /ssh-term WebSocket)
├── driver.ts         Cloud driver (chat / commands / tool forwarding / permission confirmation, sync protocol)
├── ssh.ts            Built-in SSH client (X25519 / Ed25519 / AES-256-GCM, zero dependency; exec + shell)
├── socket.ts         cloudflare:sockets TCP transport adapter
├── stores.ts         In-memory store (zero persistence)
├── webui.ts          Event protocol (same source as the local Web UI)
├── llm/ rp/ core/ ui/  Pure modules copied from the main project
└── cloudflare.d.ts   Workers type declarations
public/               Front-end trio (liquid-glass UI, copied unchanged)
```
